Interview prep · Part 2

Technical rounds

Solve problems out loud, in a repeatable order.

The patterns get clearer the more problems you solve. Try your best first. If you can't get it, study the solution; that struggle is what makes it stick.

A repeatable routine

  1. Restate the problem in your own words.
  2. Clarify: ask about inputs, edge cases, and constraints.
  3. Examples: work a small one by hand, then an edge case.
  4. Brute force first. Say it out loud, then say why it's too slow.
  5. Improve it. Look for a pattern you know (below).
  6. Code it cleanly, narrating as you go.
  7. Test with your examples, then state time and space complexity.

It's the same idea as the rest of this site: start big with the brute-force answer, then break it down.

Patterns worth knowing

  • Arrays and hash maps
  • Two pointers and sliding window
  • Stacks and queues
  • Binary search
  • Trees and graphs (DFS, BFS)
  • Recursion, backtracking, and dynamic programming
  • Heaps and sorting

Practice that sticks

  • Set a timer (about 20–30 minutes). When it ends, read a solution.
  • Then close it and write the solution from memory.
  • Come back to the same problem a week later.
  • Practice talking, not just typing. Explain aloud as if someone were listening.

Competitive programming (ICPC) is a different kind of training from interview prep, and a good complement. That track is coming soon.
